AI reply flow and RAG flow

How an inbound customer message becomes a delivered AI reply, what the RAG step does inside it, how knowledge gets into the search index, and which function to call for each job. Read from the code; the diagrams show the current behavior.

From the inbound event to delivery. Batching, pause and handoff checks, and redelivery all happen here.

2. RAG flow inside one reply

What generate_agent_reply does. Most replies take one LLM call, because search runs before the agent.

Pre-search (every reply with a KB)Agent tools (only if the model calls them)
flowchart TD
  Q["question: whole pending turn, formatted with photo notes"] --> H["build_history: max 50 msgs, 3000 token budget, after episode summary"]
  Q --> C["build_reply_context: instructions, customer memory, api_domains, order tools if ordering on"]
  C --> R{"KB collection or web crawl collection exists?"}
  R -->|no| AG
  R -->|yes| SQ["_search_query: previous user msg (300 chars) + question"]
  SQ --> QD["Qdrant hybrid search per collection: dense (OpenRouter embed) + BM25 sparse, k=10"]
  QD --> RK["rerank_docs (OpenRouter rerank): top 5 with score >= RERANK_MIN_SCORE 0.2"]
  RK --> PRE["Pre-search results go into the system prompt"]
  PRE --> AG["LLM agent call (usually the only one)"]
  AG -->|tool: retrieve_business_context| T1["Agent's own keyword query, same search pipeline"]
  AG -->|tool: escalate_to_human| T2["Sets handoff_reason"]
  AG -->|tool: call_api, if api_domains set| T3["Logs api_call for the reply"]
  AG -->|order tools, if ordering on| T4["Product and order tools"]
  T1 --> AG
  T2 --> AG
  T3 --> AG
  T4 --> AG
  AG -->|final text| OUT["reply text + trace (sources, tool calls, tokens), usage tracked per project"]

4. When to call what

Pick the row for the job you are doing. Only the first row is the normal entry point.

SituationCallNotes
New customer message arrivesschedule_reply(msg)The only normal entry point. Do not call process_reply directly.
Photo or audio arrivesstore_message_media.delay(msg.id, wants_reply)Calls schedule_reply when done.
Need the RAG answer for a message, inside the pipelinegenerate_agent_reply(msg, kb, question=...)DB reads only, so call it outside a transaction.
RAG without history, memory, billing or deliveryagents.rag.generate_reply(question, Context, ToolDeps, history, project_id)For tools or tests only. It sends nothing.
Search onlyget_retriever(collection), then rerank_docs(query, docs, top_k, min_score, project_id)Use this for a search-only feature.
Add knowledgeadd_texts_to_collection(...) or queue run_ingestion_jobUse the job when you need status tracking.
Send a reply to the customerdeliver(conversation, out_msg, reference_msg)Failed sends go to redeliver.
Staff reply to a customer messageNot tracedOutside the scope read for these diagrams.

Notes

  • Settings that change the flow: REPLY_DEBOUNCE_SECONDS (3s for facebook, instagram and whatsapp), RERANK_MIN_SCORE (0.2), MEMORY_UPDATE_DELAY_SECONDS (300).
  • Scheduled tasks that touch this path: recover-stuck-replies every 5 min, summarize-idle-episodes every 30 min, reconcile every 10 min.
  • Changing the embedding model requires re-indexing every Qdrant collection (noted in the code).
